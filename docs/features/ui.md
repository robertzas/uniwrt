# UI/UX & design system

Read this when building any page, component or visualization.
Milestones: M0.3 (skeleton), M1.8 (app shell and design system v1), every feature WP, M9.1 (polish).

## Goals

Professional, modern and fast: dense but calm. It should feel like a premium product, with Linear/Vercel-level polish and UniFi-level network clarity. Excellent on desktop and genuinely useful on a phone.

## Stack (D-002, D-018, D-045)

- SolidJS 2.0 release candidate with `@solidjs/web` (D-045); move to GA releases as they age in
- Vite, strict TypeScript
- Tailwind CSS v4 with design tokens as CSS variables
- Kobalte 2 (accessible headless primitives; patched, D-045), @solidjs/router 2 (config routes, plain `<a>` links)
- @tanstack/solid-query 6 for server state, plus WebSocket deltas
- Lucide icons through `ui/Icon` (the framework-free `lucide` data)
- uPlot for time series; d3-force (in a Web Worker) with Canvas for the topology
- @tanstack/virtual-core, wrapped in `ui/`, for large tables
- xterm.js and CodeMirror 6, lazy-loaded
- Biome; Vitest with Testing Library; Playwright e2e tests against demo mode

## Visual language

- **Themes:** dark-first plus a light theme; follows the system setting, with a toggle.
- **Token implementation:** `web/src/ui/tokens.css` defines each color once with `light-dark()`; `<html data-skin>` re-binds the tokens for the glass and UniFi-familiar skins (surfaces, borders, text, accent, `rounded-card`/`rounded-control`, `shadow-card`, `--blur-panel`, `h-row`, `w-sidebar`), so components never branch on the skin; the `glass:` variant adds glass-only effects. `tokens.test.ts` checks the contrast promises below for every skin and theme. `<html data-theme>` forces a theme, saved per browser and applied before the first paint by `public/theme-init.js`. Text tiers and the accent meet WCAG AA (4.5:1) on every surface; status, band and link colors meet 3:1 and are always paired with text or an icon.
- **Tokens:** surface levels, borders, text tiers, accent, and status (ok/warn/crit/info). Two token families are used identically in every chart, graph and legend:
  - **band colors:** 2.4 GHz amber, 5 GHz cyan, 6 GHz violet
  - **link-quality ramp**
- **Type:** Inter for the UI and JetBrains Mono for MACs, IPs and values, with tabular numbers.
- **Motion:** subtle (150–250 ms) and meaningful (state changes, live flows). `prefers-reduced-motion` is respected.
- **Density modes:** comfortable and compact.
- **Skins (D-046):** Graphite pro (default), Midnight glass and UniFi-familiar, each with light and dark. Skin and theme are separate choices, saved per browser and applied before the first paint by `public/theme-init.js`.

## Information architecture

- **Sidebar:** Dashboard · Topology · Devices · Clients · Wi-Fi · Networks · Internet · Security · Insights (Logs, Events, Alerts, Metrics, RF, Floor plans) · Updates · Settings.
- **Global:**
  - top bar: site health pill, search, pending changes, notifications, user menu
  - **⌘K command palette:** navigate, find any client/device/MAC/IP, run actions ("reboot AP2", "optimize channels")
  - keyboard shortcuts, toasts, breadcrumbs
- **Device page tabs:** Overview · Radios · Ports · Clients · Mesh · Config · Logs · Tools · Terminal (Overview, Ports and Config so far, in the URL as `?tab=`).
- **Client page tabs:** Overview · Timeline · Signal (M2.3) · Traffic (M2.4) · Doctor (M8).

## Interaction patterns

- **Staged changes:** edits collect in a Pending changes tray. **Review** shows a UCI diff per node and an impact summary ("Wi-Fi restarts on 3 nodes, about 5 s"). **Apply** shows live job progress. Any revision can be rolled back from history.
- Everything is live through WebSocket deltas; there are no refresh buttons. Skeleton loaders while loading. Optimistic UI only for harmless operations.
- Empty states give guided next steps, and every alert links to a fix.
- First-run, ISP, adoption, mesh and RF optimization are wizards, each ending in a review step.
- Forms validate client-side using the generated types and show the server's validation messages.

## Performance budgets

- Initial JS ≤ 150 KB gzip; routes lazy-loaded; Lighthouse score ≥ 95.
- 60 fps topology with 300 entities; tables virtualized above 200 rows.
- CSS containment to avoid layout thrash; WebSocket deltas applied in batches once per animation frame.

## Accessibility & i18n

WCAG 2.2 AA; full keyboard operation and focus management. Color is never the only signal (icons and patterns too). ARIA comes from Kobalte. Strings are centralized from day one, so i18n is ready (English first).

## Frontend structure

`web/src/{app, ui, lib, api/gen, features/<area>, viz/<kind>}`. Features never import other features; shared code goes in `ui/` (primitives), `lib/` (API client, WebSocket client, formatters, appearance) or `viz/` (visualizations, which use `ui/`, `lib/` and `api/`).

- **Primitives (`ui/`):** Icon, Button, Card and CardHeader, Badge and StatusDot, Stat, Sparkline, Table (virtualized above 200 rows), Tabs, Dialog (`size="wide"` for lists, `"lg"` for two-column forms) and Drawer, FormField (a labelled control with its hint or error; `INPUT` and `SELECT`, the native inputs' classes), Tooltip, Toast (`showToast`), Kbd, TextField, Checkbox (native, in the accent color), Segmented (a toggle-button group for ranges and modes), JobSteps (a job's steps as a checklist, with `jobProgress` and `currentStep`), SavedRevision (a change saved as the site's next revision, with the link to Review and apply) and JobOutcome (`JobErrorNote`, `JobSuccessNote`, `RequestError`). Interactive ones wrap Kobalte.
- **Shell (`app/`):** the sidebar (an icon rail in UniFi-familiar, a drawer on phones), the top bar (title, search, the drift `DriftChip` (admins: the drifts not acknowledged, counted, with a popover that opens each device's Config tab and Review & overwrite), the pending changes `PendingChanges`, the alerts bell `AlertsBell`, health), the Appearance menu (skin and theme), the ⌘K palette (`app/commands.ts`; features add their commands there) and a page error boundary.
- **Signed-out screens (`features/auth`):** first-run setup, "setup closed" and login; `app/App.tsx` shows them until there is a session, then the shell (D-047).
- **First run (`app/setup`, adoption.md, Path E; D-082):** `/setup`, a full page that `app/App.tsx` shows without the shell and opens once the first admin is created; the dashboard's welcome and ⌘K lead there while no gateway is adopted. `SetupWizard` (the frame, the stepper, the drafts, the save: one revision), `RouterStep` (the router found or named, its host key, adoption as the gateway and management, the jobs live; a configured router's password and the choice between starting fresh and keeping its configuration), `InternetStep` (the ISP list, then `features/internet`'s `WanSettings` and `TestPanel` over `createWanForm`), `AddressStep`, `WifiStep` (errors once Continue is tried; countries from `lib/countries.ts`), `ReviewStep` (the choices in words; the plan saved and checked with the router, shown with `features/changes`' `ImpactCard` and `NodePlanCard`; the apply with `ApplyProgress`), and `plan.ts` (pure: the address plan and its checks, the Wi-Fi checks, `withSetup`, which puts every choice into the site's document). `app/` may compose features; features still never import each other.
- **Live data (`lib/`):** `api.ts` (typed routes; the CSRF header on every POST; a 401 ends the session; `errorText` for a failed call), `ws.ts` (`LiveSocket`: topics, reconnect, a flush per animation frame), `live.ts` (`LiveContext`: the fleet, the alerts firing and the site's revisions; `createNodeView` for `node:<id>`), `alerts.ts` (the `alerts` topic as a store, what the bell counts, alerts in words, their pages), `entities.ts` (entity text parsed, named and linked), `metrics.ts` (each metric's name and unit, values with units), `jobs.ts` (`createJobsView` for the `jobs` topic, `adoptionOf`), `clientList.ts` (`createClientsView` for the `clients` topic, `averageScore`, `scoresByNode`), `config.ts` (the `config` topic as `Live.config`: the latest revision and what each node holds; `holding`, where a restore of the revision a node holds counts as current; `pendingNodes`, the managed nodes the latest revision has yet to reach; `lastApplied`, what discarding goes back to), `session.ts` (`SessionContext`: the user, sign-out), `site.ts` (`saveSite`: an edit of the latest document saved as the next revision, edited again once after a 409), `names.ts` (host and DNS names and MAC addresses as the document checks them; a client's name made a host name), `format.ts`.
- **Async and navigation:** the router holds a navigation while async data the page reads is pending, so data that is slow and polled often (discovery waits up to 3 s per request) is polled into a plain signal, not a query (D-048).
- **Visualizations (`viz/`):** `theme.ts` (tokens resolved for a canvas, theme changes); `timeseries/` (observability.md, Charts): `TimeChart` (uPlot), `MetricChart` (a feed's stored series on a chart), `feed.ts` (`createMetricsFeed`: stored series polled into a signal for a range; `createSeriesListing`), `ranges.ts`, `units.ts` (scale and color per unit and metric; formats from `lib/metrics.ts`), `data.ts` (lines on one axis, the value scale, totals), `ChartToolbar` and `RangePicker`; `topology/` (observability.md, Topology): `graph.ts` (the live topology by id), `scene.ts` (what each view draws), `layout/` (the tidy tree; d3-force in `worker.ts`, started with the first force view, or on the main thread), `render/` (the canvas renderer: palette from the tokens, icons, geometry and hit tests, drawing, gestures; `fixed` keeps the camera fitted, for the mini-map) and `TopologyCanvas`.
- **Dashboard (`features/dashboard`, observability.md):** `/`: `health.ts` (the health header's states, WAN interfaces, top clients, the score spread; pure), the health header, the Internet card (the gateway's record polled every 30 s, and the newest speed test's grade and rates), the mini-map (`viz/topology`, fixed), top clients, the Wi-Fi experience ring and the recent events (`RecentEvents`, the WS topic `events?min=notice`).
