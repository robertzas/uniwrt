# Networks, addressing & gateway services

Read this when working on IPAM, networks/VLANs, DHCP/DNS, IPv6, the firewall, VPN or other gateway services.
Milestones: M4.2 (IPAM, networks, firewall), M8.1 (services), M8.2 (VPN).

## Address plan (IPAM)

The site address space defaults to **10.0.0.0/16** and is configurable at first run (any RFC 1918 range, plus a ULA for IPv6).
Each network gets a /24 whose third octet is its VLAN ID (D-077); a VLAN with no third octet in the space takes the first free /24. The suggestions (`uniwrt_model::site::ipam`, `GET v1/ipam/network`, `GET v1/ipam/reservation`) only propose: any subnet that validates may be typed.

| Network | VLAN | Subnet | Gateway | Notes |
|---|---|---|---|---|
| Default (LAN) | untagged | 10.0.0.0/24 | 10.0.0.1 | .2–.31 infrastructure (nodes, controller) · .32–.99 static reservations · .100–.249 DHCP pool |
| IoT | 30 | 10.0.30.0/24 | 10.0.30.1 | Internet allowed; blocked from the LAN |
| Guest | 40 | 10.0.40.0/24 | 10.0.40.1 | Internet only; client isolation |
| Management (optional) | 99 | 10.0.99.0/24 | 10.0.99.1 | Moves nodes off the user LAN |

Usual VLANs: IoT 30, Guest 40, Management 99, others 50, 60, … (the next free one when taken). "Fix IP" keeps the client's current address when no reservation has it, else takes the first free one of .32–.99.

IPAM guarantees:
- No overlapping subnets; gateways and pools sit inside their subnet; reservations are unique (validation).
- No collision with the WAN side: CGNAT 100.64.0.0/10 and a static WAN's subnet (validation), and the subnet the gateway's uplinks hold now, such as an ISP modem's (render refuses the plan).
- 192.168.1.0/24 stays free for adopting factory-default devices (a warning).

## Networks

Fields:
- name; purpose (default | iot | guest | mgmt | custom); VLAN
- IPv4: subnet, DHCP pool, lease time, reservations, options (DNS and NTP servers, domain, PXE boot, custom `<code>,<value>`)
- IPv6: off | ULA | delegated | both (the hint is the VLAN ID); how clients get addresses: SLAAC only, SLAAC with stateless DHCPv6 (default), SLAAC and stateful DHCPv6 (as OpenWrt ships), stateful DHCPv6 only (Android gets no address)
- inter-network policy (see Firewall) and client isolation
- mDNS reflection membership and IGMP snooping

Port profiles (per node, D-077): an Ethernet port carries one network untagged (its native network, or none) and tagged ones (all with a VLAN, none, or a list), and says whether the mesh's wired backhaul may take it over (`backhaul`, default yes; mesh.md, Wired backhaul). A port without a profile is a trunk: the untagged network untagged, every VLAN tagged. Ports are named by device (`lan2`, `eth1`) or, on a swconfig switch, by number (`switch0:3`). The untagged network is never tagged.

Rendering:
- **Every node [M3.3]:** one bridge, `br-lan`, carries every network (D-067). With VLAN networks it filters VLANs: a `bridge-vlan` per network (the untagged network gets the lowest free VLAN ID inside the bridge), each network's interface on `br-lan.<vid>`, Ethernet ports as their profiles say (trunks by default), `bat0` always a trunk, Wi-Fi joining through its interface. A swconfig switch gets a `switch_vlan` per network, tagged on the CPU port, its user ports as their profiles say, and the CPU port's `<cpu>.<vid>` devices join the bridge as access ports. A port that carries nothing leaves the bridge (on a switch, every VLAN). Profiles naming a port the node lacks, its WAN port or one the backup line or a raw interface takes are left out with a warning; on an AP, a linked port that would drop the node's own network warns (the apply's rollback catches a lost uplink).
- **Gateway:** one static `interface` per network (`list ipaddr`, `ip6assign 64`, `ip6hint` = VLAN ID in hex, `ip6class` `local` for ULA-only or the delegating interface for delegated-only); dnsmasq `dhcp` sections with the pool as `start`/`limit` and the options as `list dhcp_option` (6, 42, 15, then custom), PXE as a `boot` section keyed by `networkid`; odhcpd per the clients mode (`dhcpv6`, `ra_slaac`, `ra_flags`); reservations as `host`, records as `domain` and `cname`.
- **APs:** layer 2 only. Every port is bridged, the WAN port too. Management uses a DHCP client on the management network, else the default one; the other networks are `proto none`.
- Bridge-wide in v1: IGMP snooping is on when any network asks for it. Client isolation renders on the network's WLANs (`isolate`) and, for the untagged network, as batman's `ap_isolation`; wired isolation and per-VLAN batman isolation come later. mDNS reflection needs M8.1's services.

## DHCP & local DNS

- dnsmasq on the gateway: pools, reservations (created with "Fix IP" on the Clients page) and options (NTP, DNS, domain, PXE). Lease events stream to the controller and feed the client inventory.
- Local DNS: `<hostname>.lan` is automatic, plus custom A/AAAA/CNAME records. `uniwrt.<domain>` points at the controller: an apply reads the controller's address from the gateway's `SSH_CONNECTION` and renders a `domain` record `uniwrt` when that address sits in one of the networks; a custom record can't take the name.
- **Upstream DNS** [M8.1a1, D-132] (`services.upstream`, schema v12): the ISP's (the WAN's servers, as OpenWrt ships), up to 4 custom servers (IPv4 or IPv6; dnsmasq `noresolv` with a `server` each), or DNS over HTTPS through https-dns-proxy: up to 4 resolvers, each an `https://` URL with 2 to 4 plain bootstrap servers (none where the host is an address: the proxy's own list then; one alone makes the proxy abort), each its own instance on `127.0.0.1` from port 5053, which dnsmasq forwards to alone. The proxy never touches dnsmasq or the firewall (`dnsmasq_config_update '-'`, `force_dns '0'`; render owns both), its canary domains and heartbeat are off, and the NTP servers' names resolve through the first bootstrap server (IPv4 first), since DoH's TLS needs the right time first. The UI offers presets (Cloudflare, Quad9, Google, NextDNS, AdGuard) that fill URL and bootstrap. APs keep dnsmasq off and forward nothing.
- **Per-network DNS:** a pool hands out other DNS servers (option 6) instead of the gateway (M4.2a); blocklist bypass per client is a firewall redirect (below).
- **Blocklists** [M8.1a2, D-132, D-133] (`services.blocking`, schema v13; off by default): lists from a curated catalog (ads and trackers: HaGeZi Light/Normal/Pro, OISD Small/Big, StevenBlack; malware: URLhaus, Phishing Filter, HaGeZi Threat Intelligence Mini; turning blocking on starts from HaGeZi Normal + URLhaus) and up to 16 custom URLs (hosts, plain domains, adblock `||domain^` or dnsmasq lines), plus up to 1,000 allowed and 1,000 blocked domains (each with its subdomains). The controller downloads them nightly (in the site's 04:00–06:00 window once the oldest copy is about 20 h old, at any time past 48 h, at once for a list never fetched) and on demand (`POST v1/services/blocklists/refresh`), keeping the last good copy of each, deduplicates them and compiles one `servers-file` (`server=/domain/` blocks, `server=/domain/#` re-allows under a blocked parent; capped at an eighth of the gateway's memory, the user's own blocks and the malware lists kept first). The gateway gets the settings of the revision **applied** to it (list choices, allow and deny reach it with an apply; refreshed list content without one), and only while that revision manages its `dhcp`: the controller compares the SHA-256 in the file's header line, which the gateway's `services` set reports, with its compile, and pushes on a mismatch while the gateway is online and no job holds it. `GET v1/services/blocklists` shows the catalog, each list's download state, the compile (domains, cut, capacity) and the gateway's copy (synced, pushing, failed, waiting, offline, busy, off or unmanaged). While blocking is on, the gateway's main dnsmasq reads `*.conf` from `/tmp/dnsmasq.uniwrt.d`, where the push writes the list and the conf file that loads it; a refresh is read again on SIGHUP. Until the first push, and after a reboot until the controller pushes again, dnsmasq resolves unfiltered (it can't start with a missing servers-file). **UI** (M8.1a2b1): `/networks` has a DNS filtering card beside upstream DNS: the gateway's copy (synced with its domain count, pushing, failed with the error, offline, …), a note while the saved settings wait for an apply, the compile's cut against the gateway's capacity, figures (domains blocked, lists, allowed domains, bypassing clients) and each list's download state; the state is read every 3 s while lists download or go out, else every 30 s. Admins refresh the lists and edit the settings in a dialog: on/off (turning it on with nothing to block starts from the default lists), the catalog by category with each list's size and the chosen total against the capacity, custom lists, allowed and blocked domains one per line (lowercased, `*.` dropped, checked as the model checks them), bypassing clients picked by name or typed MAC, and query statistics.
- **Bypass** (per client, by MAC): the firewall redirects the client's DNS (port 53, TCP and UDP, IPv4 and IPv6, in every network's zone: `uniwrt_dns_bypass_<network>`) to a second dnsmasq instance on port 5354 with the same upstream (DoH included), which asks the main instance for local names. The instances are then named `main` and `unfiltered`, and the pools name `main` (`option instance`), so only the main one serves DHCP.
- **Query statistics** [M8.1a2a2, D-133] (`services.blocking.stats`, schema v14; on, and in effect while blocking is): both dnsmasq instances log every query (`logqueries`, which OpenWrt 24.10 and 25.12 pass as `--log-queries=extra`: each line carries the query's serial and the client's address) and the gateway's log buffer grows to 256 KiB. The lines reach the controller with the rest of the log (the agent, or syslog) but are never stored as log entries: they go to the statistics through a queue of their own (8,192 lines; syslog gives them their own rate per sender and at most half its queue). Each query is paired with its answer line (by serial; in the plain form, the line after it): forwarded, cached, local (hosts files, leases, configured names), blocked (`config <name> is NXDOMAIN` for a name of two labels or more, not a reverse lookup and not under the site's local domain) or failed (`REFUSED`/`SERVFAIL`); a query with no answer line (it joined one in flight) counts as forwarded after 5 s. Queries from the gateway itself (loopback) are left out, and a query at or below the highest serial seen of its dnsmasq process (the agent's backfill, or syslog and the agent both delivering it) is skipped. The client is named by the MAC of the client holding its address, else by the address. The controller keeps 24 h of queries and 30 days of hourly counts per client (queries, blocked), stored every 2 s; top domains and top blocked are read from the queries. The API (M8.1a2a2b) serves `GET v1/services/dns/stats?range=24h|7d|30d` (the range's totals, its hourly series summed over clients, each client's totals named by its alias or DHCP hostname, by MAC or by the client now holding the address, and the 20 top answered and top blocked domains of the last 24 h, through a covering index on outcome and domain) and `GET v1/services/dns/queries` (newest first, filtered by client (a MAC, or the address of a client no MAC was known for), outcome and domain text, a page of up to 1,000 at a time with a `<time>:<id>` cursor). The demo's gateway logs queries while its `dhcp` sets `logqueries`: popular names, local ones and names of the blocklist it was pushed, the bypassed clients through the unfiltered instance. **UI** (M8.1a2b2): `/networks` has a DNS queries card under DNS filtering while the latest revision has blocking and statistics on: 24 h, 7 days or 30 days of totals (queries, blocked, the blocked share, clients), the queries as stacked bars (answered and blocked; by hour over 24 h, by local day otherwise), the busiest clients (linking to their page, and to their queries) and the top answered and top blocked domains of the last 24 h, read every minute. Admins allow a blocked domain or block an answered one from there or from the query log, as the next revision (it reaches the gateway with an apply); a domain the allow or deny list already covers says so. The query log (a dialog) filters by client, outcome and domain text and reads older pages on demand.

## IPv6

- The gateway gets a delegated prefix (DHCPv6-PD) or uses 6rd, then hands out a /64 per network (`ip6assign`, with `ip6hint` set to the VLAN ID in hex).
- An `fdxx::/48` ULA is always present for stable local addressing.
- RA/SLAAC by default; stateful DHCPv6 optional.
- The IPv6 firewall mirrors the IPv4 policy.

## Firewall policy [M4.2] (D-079)

- One zone per network, plus wan.
- Inter-network policy is a matrix (from → to: allow | block), seeded by purpose; `firewall.policies` override cells. Replies to connections the other side opened always pass (fw4 accepts established traffic in every direction), so a blocked cell whose reverse is allowed is "replies only"; the model's `established` action renders as block.
  - LAN and Management → everything: allow.
  - IoT → LAN: block (replies pass). IoT → internet: allow.
  - Guest → internet only; Guest → gateway: DHCP and DNS only (the zones that don't reach the gateway get `Allow-<zone>-DHCP`/`-DNS`, and with IPv6 `-DHCPv6`/`-ND`).
- **Port forwards** (`firewall.forwards`, DNAT): a unique name (not `DMZ`), on or off, TCP, UDP or both, a WAN port or range, the host (an address in a network's subnet, not the gateway's, the subnet's or its broadcast) and its first port when it differs (a range keeps its length), an optional source subnet, and NAT reflection (on by default: hosts on the networks reach the forward through the WAN's address too). Enabled forwards may not share a port and protocol. Forwards behind DS-Lite or an IPv6-only WAN warn: the internet can't reach them over IPv4.
- **DMZ host** (`firewall.dmz`): every connection from the internet that no forward claims goes to one host.
- **UPnP IGD and NAT-PMP/PCP** (`firewall.upnp`, miniupnpd): on for the main LAN on new sites (off on migrated ones, as before), for the networks chosen. Secure mode (a client maps ports only to itself), ports from 1024 only (OpenWrt's stock permissions). The live list of mappings comes from miniupnpd's lease file with the gateway's DHCP leases (the `leases` set, every minute).
- Custom traffic rules (protocols, ports, IP sets) and time-based rules for parental schedules [M8.1]; IP/geo blocklists using nft sets (backlog). IPv6 "forwards" (opening a host's port to the internet) come with custom rules.
- Rendering: fw4 UCI (`zone`, `forwarding`, `rule`, `redirect`; `ipset` later), validated with `fw4 check` in the system harness. Each forward is a `redirect` from `wan` to the zone of the network whose subnet holds the host, with `target`, `dest_port` and `proto` always written; the DMZ is the last redirect (`name 'DMZ'`, `proto 'all'`, as LuCI writes it). UPnP is the `upnpd` package (miniupnpd's stock options and permission rules, `internal_iface` naming the networks), which needs `miniupnpd-nftables` (installed by the apply, D-076) and carries over the `uuid` miniupnpd writes on its first start; untrusted zones it serves get `Allow-<zone>-UPnP` (UDP 1900 and 5351) and `Allow-<zone>-UPnP-HTTP` (TCP 5000).
- Import: named DNAT redirects from `wan` to a host on a network become forwards (`DMZ` without ports the DMZ host); unnamed ones, ranges that change length and the like stay raw sections. miniupnpd's package becomes `upnp` (on unless `enabled '0'`; off without the package).
- UI (M4.2b2): the `/security` page. **The matrix** has a row per network and a column per other network plus Internet (the internet's row stays out: forwards are the way in); a blocked cell whose reverse is allowed reads "Replies only", and cells that differ from the purpose's seed are marked. Admins toggle cells and save them as one revision: cells left as they were keep their policies (an `established` one too), changed cells get a policy only where they differ from the seed, and cells of a network another save added stay. **Forwards** open in a dialog that checks what the server checks (names, ports, the host on a network, clashing enabled forwards, the source as an address or subnet, a bare address becoming a /32) and suggests the clients' addresses; forwards are keyed by name across revisions. **The DMZ host** is set or removed inline. **UPnP**: on or off and its networks (those with IPv4), a hint while the gateway doesn't manage `upnpd`, and the open ports with the client's name. A network can't be deleted while UPnP, a forward or the DMZ host uses it; deleting one drops the policies naming it.

## VPN [M8.2]

- A WireGuard server on the gateway. Peers get auto-assigned addresses (default 10.0.250.0/24), a QR code or `.conf` download, and full or split tunnel routes.
- The DDNS hostname is the endpoint. Handshake and traffic stats are shown per peer.
- Site-to-site peers; optional management of the Tailscale package.

## Other services [M8.1]

- **DDNS** [M8.1a1, D-132] (`services.ddns`, ddns-scripts on the gateway): up to 16 names, each with an id (its `ddns.service` section), a hostname, IPv4 (an A record from `wan`) or IPv6 (AAAA from `wan6`), the address from the WAN interface or from a web echo (`api.ipify.org`/`api6.ipify.org`, for a gateway behind another router), and a provider: Cloudflare (zone, API token; `cloudflare.com-v4`), DuckDNS (`<name>.duckdns.org`, token), deSEC (token), No-IP and Dynu (username, password), FreeDNS (afraid.org v2 token), or a custom update URL (`[DOMAIN]`, `[IP]`, `[USERNAME]`, `[PASSWORD]`; a password only where the URL names it). The token or password is a vault secret (`services/ddns/<id>/secret`). Updates go over HTTPS (except a custom `http://` URL, which warns when it carries the password) against the CA bundle; the address is compared every 10 minutes and sent anyway every 72 hours; private addresses are never published; notices and errors go to syslog. Render requires `ddns-scripts` and `ddns-scripts-services`, plus `-cloudflare` or `-noip` while such an entry runs. The `services` collect set reports each name's registered address, last update and whether its updater runs, and the running DoH instances.
- **NTP server** [M8.1a1] (`services.ntp_server`, on for new and migrated sites): the gateway answers NTP on its networks, and pools without NTP servers of their own hand it out (option 42, `0.0.0.0`: dnsmasq's own address). Brownfield import keeps a gateway's `enable_server` as it is (stock OpenWrt has it off).
- **mDNS reflection** [M8.1b1, D-136] (each network's `mdns`; on for new networks but guest and management ones): the gateway's `mdns-repeater` (21 KiB, UCI package `mdns_repeater`, section `main`, `list interface` of the networks' devices) repeats IPv4 mDNS between the networks that have it on and an address on the gateway, while there are two or more; at most 5 (the repeater's limit: validation refuses more). It runs only on the gateway (render requires `mdns-repeater`, service `mdns-repeater`); with fewer than two networks a gateway that holds the package keeps its section without interfaces, the service off. The untrusted zones among them get a rule to reach it (`Allow-mDNS-<network>`: UDP 5353 to 224.0.0.251); the default and management networks reach the gateway anyway. The repeater loses its group membership when netifd makes a device anew (a network restart), and its init script's triggers name devices where netifd expects interfaces, so the controller's footprint carries an interface hook (`/etc/hotplug.d/iface/90-uniwrt`) that restarts it when one of its devices comes up. Import reads which networks it serves from the package (none without it). Nodes that managed `dhcp` before schema v15 manage `mdns_repeater` too.
- **IGMP snooping and multicast to unicast** [M8.1b1, D-136]: a network's `igmp_snooping` turns snooping on for the bridge every network shares (netifd's `igmp_snooping` on `br-lan`; one network's on is on for all). netifd then converts multicast to unicast on every bridged AP interface by default (`multicast_to_unicast`, with hairpin): each WLAN has **Multicast to unicast** (schema v15, on), rendered as `multicast_to_unicast '0'` only when off, for clients that miss such frames; import reads it.
- **Wake-on-LAN** [M8.1b2a1, D-137]: an admin's `POST v1/clients/{mac}/wake` (a client the controller knows; audited `wake_client`) has the gateway send the magic packet with `etherwake -b -i <device>` (EtherType 0x0842 to the broadcast address, so a bridge's stale entry can't misdirect it): on the gateway's device of the client's last IPv4 subnet, else the one its lease or neighbor entry names, else on every network the gateway serves (a static address without a gateway). Stock images have no sender (no `ether-wake` applet, a TCP-only `nc`, no ucode socket module), so a **managed** gateway without it gets `etherwake` (6 KiB) from the feeds first (index refreshed, then installed; up to 5 min, answered when done: `installed` in the outcome, ✅ 24.10 opkg and 25.12 apk); an observed one is refused with a hint, unless it has it already. Refused while a job holds the gateway, or while it is offline. Answers `WakeOutcome` (`node`, `devices`, `installed`). **UI** [M8.1b2a2]: *Wake* in a client's header (admins) asks first, says while it waits that the first wake may take a minute or more (the install), keeps a refusal in the dialog in the server's words, and toasts where the packet went.
- **Restarts** [M8.1b2a1, D-137]: an admin's `POST v1/reboots` (`{"nodes": [...]}`; 202 with the job; audited `reboot`) restarts **managed** nodes (409 for one in observe mode) one at a time, as an apply orders them (farthest from the gateway first, the gateway last): `reboot` → down within 1 min → a login with its pinned host key within 10 min → if it was never seen down, an uptime shorter than the time since the command. The first node that fails ends the job, leaving the rest as they are. **UI** [M8.1b2a2, D-137]: *Restart* in a device's header (admins; disabled with the reason in observe mode or offline; *Restarting…* while a restart includes it) and *Restart…* in the devices list's toolbar (disabled until a device is managed), one dialog (`features/devices/reboot`): several devices are picked (gateway last, observed ones disabled, offline ones unchecked), one is asked about; it warns that each is offline a few minutes, that the gateway takes the internet with it, and that the first failure stops the rest; then follows the job on the `jobs` topic (each device Waiting → Restarting → Back, with how long it took), as it does a restart of the same devices started elsewhere.
- Scheduled reboots and LED schedules (LEDs off at night) [M8.1b2b, D-137: run by the controller].
- A per-node package manager UI (install, remove, upgrade). Packages required by the node's role are locked.
